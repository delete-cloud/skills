# E2E 与 PR Review 证据核验

让结论与实际被验证的行为一致。按用户任务选择测试设计、失败排查、只读 review 或历史复盘；只开展所需部分。历史复盘不默认重跑测试，只读 review 不默认修代码。

本 skill 补充验证方法，不接管 PR、CI 或生产部署流程。沿用会话中已成立的授权与适用仓库规则，不新增批准步骤，也不把审查通过视为额外操作授权。

**先确定待证明的行为。**

- 从需求、验收标准、相关 ADR、代码和实际调用路径确认目标。写清链路起点、终点和影响本次结论的未覆盖项。
- 标识验证对象：指定 commit/diff、相关工作区修改、环境、必要配置及时间。未提交改动存在时，不能仅用 HEAD 标识全部受测代码；保留对应 diff 或产物引用即可，不强制创建 worktree。
- 检查当前适用的 review 与 CI 规则。历史记忆帮助定位背景；历史规则、旧日志和代理摘要不直接代表当前状态。涉及已有决策时检索可用的 nmem 并按需回到原文；无 nmem 时可用仓库材料继续，不把该服务作为执行依赖。

**规划 e2e：区分独立的验证维度。**

仅列与目标有关的维度，每项写“实际走过的路径 → 观察与断言 → 未覆盖边界”：

| 维度 | 需要区分的路径 |
| --- | --- |
| 外部依赖 | mock/fake、真实 provider、目标身份与实际网络路径 |
| 持久化 | 内存、直接文件导出、真实 commit/load、新进程恢复 |
| 评估 | case 构造、metric 成功调用、业务质量阈值达标 |
| 部署 | 配置渲染、资源创建与运行、release 升级/回滚、生产行为 |
| 生命周期 | 创建、就绪、故障恢复、取消、清理；按变更风险选择 |

这些维度可组合，不是一条自动升级的等级链。多条分层测试各自通过，不能拼成一条未实际执行的完整路径；也不要求每次改动覆盖所有维度。

优先让集成测试消费实际交付的配置或组件，避免维护平行实现。以外部契约、可观察行为和副作用设计断言；round trip 可证明往返一致性，但格式兼容、跨进程恢复或业务质量需要各自的证据。只验证现有实现行为时，说明其用途，不据此推断需求正确。

**遇到失败：先定位，再决定改实现还是改测试。**

- 区分环境/依赖条件、测试夹具或断言问题、产品行为缺陷，以及尚未定位的失败。分类由日志和契约支撑；超时、lint 告警不能仅凭名称自动归为某一类。
- `passed`、`failed`、`skipped`、未运行、被筛选排除分别记录；区分所选 case 与全套。缺凭证或依赖的 skip 不证明真实路径成功，也不能直接归为产品失败。
- 可选真实路径可能在 skip 后藏着错误参数或接口漂移。若该路径关系到验收，用适当的静态检查、确定性契约测试或已获授权的真实执行补足证据；不要通过打印凭证来证明环境就绪。
- 调整断言时说明原契约和新断言的关系。允许模型措辞变化时，仍检查工具选择、次数、消息/结果关联、持久化内容等关键行为；若目标本来是精确输出或指令遵循，不得用“模型波动”删除该要求。
- 返回合法分数仅证明 metric 可调用；质量目标还要检查对应阈值或判据。调整 timeout 要有运行证据和适用范围，不能靠不断延长等待把性能要求消掉。
- 修复后运行受影响的必要验证。已有证据足够且没有新变化时停止重复执行；出现新失败再重新定位。

**做 PR review：把 finding、严重性和处理政策分开。**

围绕当前 diff、相关契约和必要调用路径审查。有效 finding 应说明触发条件、文件/行或其他证据、实际影响、严重性理由及修复如何验收。静态推导可成立，但须给出可达路径；无法证实的条件保留为问题或假设，不包装成已确认缺陷。

按适用项目政策处理 finding。不要把某个项目的“P2 不阻塞”或某次“无 P1/P2”结论推广到所有项目。风格、猜测、范围外强化与真实缺陷分开记录；接受、驳回、重新定级或延期都给出简短技术理由。没有既定政策时，说明具体影响及是否妨碍已约定验收，不凭空增加门禁。

复审优先检查原 finding、修复引入的风险和受影响回归。真实的新 blocker 仍要处理；与当前目标无关的建议不应不断扩大本轮范围。不要以固定 review 轮数或连续几次 APPROVE 替代验收条件。

当任务包含合并就绪判断时，对齐当前提交、必需 CI、相关未解决评论和平台状态。提交或关键配置变化后，判断哪些证据失效并补验受影响部分，不自动要求全套重跑。纯历史复盘只报告当时状态和已核实的后续变化。

**汇总：独立核对证据，不按代理票数定案。**

不默认启动额外 agent。已获授权的多 agent 工作应分清范围、版本与取证责任，先独立分析，再有目的地交叉核对。最终采用原始证据支持的判断；同一份 diff 的多个审查意见不等于多次独立运行观测。区分亲自执行、读取原始日志、接收摘要以及推断。

报告只保留影响判断的字段，可直接写进现有任务记录，无需另建一套状态包：

```text
待证明行为与范围：
版本 / 工作区差异 / 环境：
真实路径与替代部分：
实际命令、结果、筛选或跳过原因、产物引用：
finding、适用级别与处理理由：
结论直接支持什么；关键未验证项是什么：
若仍有缺口，下一步最小验证是什么：
```

静态 review 结论与运行时验收分别表述。未执行的步骤写为计划，不继承其他环境的成功；范围内没有发现问题，也不外推为全系统不存在缺陷。

判断断言调整、skip、存储恢复、P2 政策或多 agent 分歧时，可按需读取 [历史案例与适用边界](references/cases.md)。这些案例说明决策方法，不定义当前项目状态或强制流程。
